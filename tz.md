# Техническое задание: Мультиадминка для создания административных панелей

## Описание проблемы

У компании возникает множество запросов на разработку типовых административных систем (CRUD для различных сущностей + простой UI), что требует ручной разработки новой кодовой базы, инфраструктуры, деплоя и минимальной автоматизации. Необходимо создать платформу, позволяющую визуально генерировать новые административные панели с нужной структурой, логикой и разграничением доступа.

---

## Решение

Создать мультиадминку, где администратор может через веб-интерфейс создавать новые проекты-панели, задавать структуру данных, настраивать webhooks и разграничивать доступ для партнеров.

---

## Роли

- **Админ** — создает проекты, сущности, webhooks, партнерские аккаунты.
- **Партнер** — управляет данными в «своем» проекте: просматривает, редактирует, удаляет записи, экспортирует в Excel.

---

## Технологический стек

### Backend

- **Node.js** — актуальный, масштабируемый и быстрый серверный движок. Множество библиотек для работы с web, REST, очередями, интеграциями.
- **Express** — популярный фреймворк для построения REST API, легкий, гибко расширяемый.
- **Sequelize** — удобный ORM для работы с PostgreSQL, позволяет динамически формировать модели на основе метаданных.
- **PostgreSQL** — реляционная БД, хорошо подходит для сложных и динамических схем, поддерживает миграции и jsonb-поля.
- **Docker** — контейнеризация приложения для удобного деплоя и масштабирования.

#### Альтернативы и замечания

- Если нужен более сложный workflow/автоматизация, можно рассмотреть **NestJS** вместо Express — но Express проще для MVP.
- Вместо Sequelize для сложной динамики можно использовать **TypeORM** или **Prisma** — но Sequelize оптимален для динамического формирования моделей через JS.
- Для хранения некоторых конфигов сущностей можно использовать jsonb поля PostgreSQL.

### Frontend

- **React** — современный фреймворк для построения динамического UI, хорошо работает с формами, таблицами, визуальными конструкторами.
- **Redux** — state management для сложных форм и взаимодействий.
- **MUI (Material UI)** — быстрая разработка красивых административных интерфейсов, готовые компоненты для таблиц, форм, валидаций.

#### Альтернативы и замечания

- Для state management можно рассмотреть Recoil/Zustand, но Redux привычен для сложных админок.
- Для таблиц с экспортом в Excel можно использовать MUI DataGrid или handsontable, возможно понадобятся специализированные компоненты.

## Функциональный флоу (Backend)

### 1. CRUD генератор сущностей

- Внутри проекта админ визуально создает сущности (например «Заявка», «Участие»), описывает поля, типы (строка, число, дата), валидации (регулярки, обязательность, уникальность).
- Сохраняется метаописание сущностей и их полей в базе (например, в таблицах типа `entity`, `entity_field`).
- На основании этого метаописания API динамически формирует маршруты и Sequelize-модели. Новые сущности не требуют перезапуска приложения.

### 2. Генерация API

- Для каждой сущности автоматически создаются CRUD-эндпоинты:
  - GET (список, фильтрация, пагинация)
  - POST (создание с валидацией)
  - PUT/PATCH (редактирование)
  - DELETE (удаление)
- Валидация данных на backend, согласно описанию полей.
- Авторизация по JWT, разграничение доступа к данным по ролям и проекту.

### 3. Webhooks

- Для каждой сущности можно задать webhooks:
  - slug (уникальный адрес)
  - формат тела (raw, formData)
  - условия отправки (например, при создании записи)
  - пересылка данных на указанный endpoint (внешняя интеграция)
  - email-уведомления при успешной операции

### 4. Партнерские аккаунты

- Админ создает партнеров, назначая им доступ к конкретным проектам и сущностям.
- Партнер при входе видит только свои проекты и связанные с ними данные.

### 5. Таблицы и экспорт

- Партнер может просматривать, фильтровать, редактировать, удалять записи.
- Экспортировать данные в Excel (генерация xlsx на сервере или фронте).
- UI таблицы строится динамически на основе описания сущностей из backend.

### 6. Инфраструктура

- Монолитное приложение (для MVP).
- Поддержка многопроектности: данные разных проектов разделяются либо отдельными схемами, либо через метаданные (например, поле project_id).
- Docker для деплоя, настройка nginx для поддоменов (если нужно, возможно через traefik).
- Логирование операций (audit trail).

---

## Особенности реализации

- Генерация моделей в рантайме (Sequelize поддерживает динамическое создание моделей).
- Валидация: можно использовать Joi/Validator.js, валидации из метаописания.
- Миграции: при добавлении новых сущностей/полей — либо физически изменять схему (ALTER TABLE), либо работать через jsonb поля (если изменения слишком частые).
- Хуки и интеграции: очередь через Bull или RabbitMQ для надежной отработки webhooks/email.
- UI конструктор: для админа — drag'n'drop создание сущностей, полей, валидаций, webhooks.

## Пример структуры БД (метаописание)

- `projects` — проекты
- `entities` — сущности
- `entity_fields` — поля сущностей
- `entity_records` — сами данные (либо отдельные таблицы, либо jsonb)
- `webhooks` — описание хуков
- `partners` — аккаунты партнеров
- `users` — все пользователи (админ, партнеры)
- `audit_logs` — журнал операций
